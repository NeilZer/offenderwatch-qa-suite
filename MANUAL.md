# User manual — OffenderWatch QA suite (Parts 1–4)

How to install the suite, run the checks, read the results, and open the QA dashboard.
For the Test Management Platform (Part 5) see `../SuperCom-Platform/MANUAL.md`.

---

## 1. One-time setup (about 5 minutes)

You need **Node.js 20 or newer** (`node -v` shows the version).

Open a terminal in this folder: in VS Code, **Terminal → New Terminal**, then:

```powershell
cd C:\Users\Neil\Desktop\SuperCom
npm install                       # downloads Playwright and TypeScript
npx playwright install chromium   # the browser used by the UI tests (skip if already installed)
copy .env.example .env            # your settings file
```

Open `.env` and check the address of the application under test:

```
BASE_URL=https://svcdemoaz.puremonitor.supercom.com/AQApplication/Neil/
```

That's the only place a URL is configured. Change it to test another instance.

---

## 2. Running the checks

| I want to… | Command | Time |
|---|---|---|
| **Run everything and update the docs + dashboard** (the official run) | `npm run qa` | ~1 min |
| Watch the UI tests in a visible, slowed-down browser | `npm run demo` | ~3 min |
| Run all tests without touching the dashboard | `npm test` | ~1 min |
| Run only the API tests / only the UI tests | `npm run test:api` / `npm run test:ui` | 15 s / 45 s |
| Run one test case | `npx playwright test -g "TC-38"` | seconds |
| Run everything for one requirement | `npx playwright test --grep "@FR-04"` | seconds |
| Open the detailed report of the last run | `npm run report` | — |
| Run and report into the Part 5 platform | `npm run platform` | ~1 min |

Only `npm run qa` updates the dashboard and the documents. Single-test runs and the demo never overwrite them.

## 3. Reading the results

### In the terminal

```
  ok  12 [api] › … TC-05 list response contract and last-name sort order
  x   13 [api] › … TC-03 totalPages equals ceil(total / pageSize)
  71 passed (44s)
```

| You see | Meaning | What to do |
|---|---|---|
| `ok` | The requirement works. | Nothing. |
| `x` | The test fails **because of a documented bug** (BUG-01 … BUG-18). This is expected while the bug is open. | Nothing; the bug is reported. |
| A **red** failure, on a test that is not marked as a known bug | **New problem**: a regression, or the environment/test is broken. | Open the report (`npm run report`) and investigate. |
| A red "**Expected to fail, but passed**" | The known bug looks **fixed**. | Retest the bug, then remove `knownBug('BUG-xx')` from the test. |
| `71 passed` on the last line | Everything behaved as predicted: working features pass, known bugs still fail. | — |

### In the detailed report (`npm run report`)

Click any test to see every step and API call (method, URL, status code), screenshots, the trace of a failure,
and, for the edit bug, the exact request the UI sent.

## 4. The QA dashboard (Part 4)

Open `dashboard\index.html` (double-click, or `start dashboard\index.html`). It needs no server and works offline.

| Section | What it tells a manager |
|---|---|
| **GO / NO-GO banner** | The release recommendation, with the reason. NO-GO means Critical or High bugs are still open. |
| **Five tiles** | Test cases · executed · passed · failed · blocked / not run, with percentages. |
| **Test execution** | Pass rate, and the passed / failed split. |
| **Automation** | How many cases are automated (UI / API) or manual, and the result of the latest run. |
| **Defects** | Bugs by severity (Critical / High / Medium / Low) and by status (Open / Fixed / Retest). |
| **Requirement coverage** | One card per requirement (FR-01 … API-05): passed or failed, how many cases, which bugs. |
| **Open defects** | All 18 bugs, most severe first. |
| **All test cases** | Expand to see all 52 cases with their result. |

The dashboard is regenerated by `npm run qa`. No number on it is typed by hand.

## 5. The documents

| File | Contents |
|---|---|
| `docs/TEST_CASES.md` | Part 1: the 52 test cases, the traceability matrix (requirement → cases → result), and every case's steps. |
| `docs/test-cases.csv` | The same suite, opens in Excel. |
| `docs/BUG_REPORTS.md` | Part 2: the 18 bug reports, with steps, expected vs actual, the layer analysis and evidence. |

These are generated from `qa/test-cases.json` and `qa/bugs.json`. To change a test case or a bug, edit the JSON and
run `npm run docs` (or `npm run qa`).

## 6. Common problems

| Problem | Fix |
|---|---|
| `Missing required environment variable BASE_URL` | Create `.env` from `.env.example` (step 1). |
| Many tests fail with timeouts or network errors | The application is unreachable: open `BASE_URL` in a browser. |
| `ENOSPC: no space left on device` | The disk is full: free space and run again. |
| The top-bar "Trail points" number keeps growing | Expected: deleting a test offender leaves its points behind (**BUG-02**). |
| Something is red that isn't a known bug | Run that test alone (`npx playwright test -g "TC-xx"`), then open `npm run report`. |
